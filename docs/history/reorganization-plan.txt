# Documentation and repository reorganization plan

This plan is for the agent doing the reorganization. It is separate from [ROADMAP.md](ROADMAP.md) and adds no features. It has two goals:

1. **The docs can be trusted and navigated.** Every statement matches the code, a check enforces that in CI, and every feature has an obvious home.
2. **The repository can be navigated.** The root currently holds 98 entries, including 51 `.bend` files. After the work, the root holds only entry points and top-level docs, and every folder has one purpose.

Two things must not change: the behavior of new runs, and the ability to verify, replay and resume existing archived runs.

---

## Ground rules

1. **No behavior changes.** Move files and fix paths; never change logic in the same PR as a move. If a move needs a code change beyond an import path or a path constant, make that change in its own earlier PR.
2. **Use `git mv`** so history and blame follow the files. Keep each move PR to moves plus the path edits they force.
3. **Toolchain is fixed:** Bend 2.0.40 and Node 24.22.3, as in CI.
4. **Every PR passes the gates in [Verification gates](#verification-gates),** including full CI with Bend and the BendTT verdicts and the Windows job.
5. **Docs move with code.** Each PR updates every doc path it breaks. After phase 1, the docs check (D1) catches the ones you miss.
6. **Ask the owner** about anything listed under [Decisions for the owner](#decisions-for-the-owner) before starting the phase that depends on it.

---

## Constraints the move must respect

Read these before planning any move. Each one has broken, or would break, real workflows.

### C1. Archived code is flat, and the MCP server enforces it

A run stores its runner and Bend sources in `<run>/code/`, keyed by bare file name. `sourceFiles()` in `experiment.mjs` reads them relative to the runner's own folder (`here`). The archived runner later runs from `<run>/code/`, so everything it reads must sit beside it.

`mcp/context.mjs` (`archiveInfo`) rejects any snapshot name that doesn't match `^[\w.-]+\.(mjs|bend)$`, so a name containing `/` makes the archive unusable through MCP.

**Consequence:** every file that `sourceFiles()` adds, plus every Bend module those import, must live together in **one flat folder**. Moving that set as a unit, with no byte changes, keeps the archived source set identical. That folder is called `core/` below (see decision R1). The set today:

- **Runner (Node):** `experiment.mjs`, `experiment_config.mjs`, `assessment.mjs`, `finite_world.mjs`, `packed_world.mjs`, `agent_source.mjs`, `process_output.mjs`, `parallel_trials.mjs`.
- **Bend library:** the import closure of `study.bend` plus the modules `sourceFiles()` and bundled agents and worlds pull in. That is `actor_critic`, `arena`, `arena_table`, `cartpole`, `cliff`, `cursor`, `doors`, `double_q`, `dyna`, `engine`, `ferry`, `finite`, `history`, `key_maze`, `logged`, `mountain_car`, `noisy_fork`, `offline`, `orchard`, `packed_world`, `parameters`, `study`, `tabular`, `tile_control` and `weights` (all `.bend`).

Regenerate this list with a script before moving, rather than trusting it. Plans can pull in more modules through bundled agents and worlds.

### C2. Modules that `experiment.mjs` imports must stay beside it

`experiment.mjs` imports `./assessment.mjs` and `./html_report.mjs` dynamically, and `html_report.mjs` imports `./public_oracle.mjs` and locates `./analyze.py` by URL. Either keep these in `core/` or change the import paths in a separate, earlier PR. Recommended: also put `html_report.mjs`, `public_oracle.mjs`, `ope.mjs` and `run_notes.mjs` in `core/` as shared host libraries. Change `html_report.mjs`'s `analyze.py` lookup to the analysis folder in its own PR.

### C3. How agent and world imports get normalized

`bundleAgent(file, library)` in `agent_source.mjs` rewrites an import of a library module to `./<basename>`, but only when the import resolves to that same file inside `library` (the runner's folder). Agents and Bend worlds currently write `import ../engine.bend`.

After the move, those imports must point at `core/`, for example `../core/engine.bend`, or `../../core/engine.bend` from a per-learner folder. Because the bundler rewrites them back to `./engine.bend`, **bundled bytes and agent identities stay unchanged.** If the imports aren't updated, bundling fails with "missing agent dependency".

The import-rewriting regular expression only matches imports that start with `./` or `../` followed by word characters, dots, slashes or hyphens. Keep paths within that pattern.

### C4. Code that locates repository files from its own folder (`here` or `repo`)

All of these need path updates:

| File | What it locates |
| --- | --- |
| `batch.mjs` | `compiler()` copies `offline.bend`, `engine.bend`, `tabular.bend` and `dyna.bend` from `here` |

### C5. Manifests reference agents and worlds by relative path

The files in `experiments/` use `agentFile`, `worldFile` and `file`, relative to the manifest, such as `../agents/sarsa.bend`. Moving an agent or world means editing those manifests. Identities are unaffected because bundles are named by content hash (C3).

### C6. Command names appear everywhere

`node experiment.mjs …` and `node batch.mjs …` appear in every doc, in MCP tests and in error messages. Decision R2 keeps these commands working.

## Phase 1: make the docs checkable, then fix current errors

Do this first, so the checker catches path breakage during the moves.

### D1. Add a docs check (M)

Write `checks/docs_check.mjs` (Node standard library only, at the root until M2) and run it from `npm test` and CI. It fails on any of these:

1. **Broken links:** relative Markdown links that point to a missing file, or to a missing heading anchor. Use GitHub's anchor rules: lowercase, punctuation removed, spaces to hyphens, `-1` suffixes for duplicate headings.
2. **Missing paths:** paths in backticks or links that look like repository paths (contain `/` or end in `.mjs`, `.bend`, `.py`, `.json` or `.md`) but don't exist. Example paths such as `runs/…`, `/path/to/…` and `REPLAY.json` go in a short, commented allowlist inside the script.
3. **Missing command targets:** in fenced shell blocks, the file argument of `node`, `python3`, `python` and `bend` commands must exist. Paths resolve from the repository root unless the block is preceded by a `<!-- docs-check: cwd=<folder> -->` comment.
4. **Wrong counts:** a stated count must sit between markers, for example `<!-- count:core-laws -->46<!-- /count -->`, and must match the counted value. Define counters for core laws (`^law ` in `LAWS.bend`), learner laws, experiment files and benchmark worlds. Replace every hand-written count in the docs with a marked one.
5. **Coverage gaps:**
   - every file in `experiments/` appears in the manifest table;
   - every Markdown file under `docs/` is linked from somewhere;
   - every subcommand in `experiment.mjs`'s usage string appears in the command reference (D6).

Acceptance: the check runs in under five seconds and passes on `main` after D2. Its own tests cover each rule with a failing fixture.

### D2. Fix the errors already known (S)

- `README.md`, "Formal Properties": it says all statements and proofs are in `LAWS.bend` and `PROOF.bend`, but the learner laws live in six `*_laws.bend`/`*_proof.bend` pairs. Name them, or link to the laws page (D6).
- `ROADMAP.md`, phase 1 context: it says "41 laws", while the core now declares 46. Use a count marker.
- Fix everything else D1 reports.

## Phase 3: documentation restructure

Do this after phase 2, so paths are written once. The goal is one home per topic. README stays the front door; `EXPERIMENTS.md` (387 lines) is split by topic. Its last ten sections are currently filed under "Test the implementation" even though most are not about testing.

### D3. Target doc set

| File | Contents |
| --- | --- |
| `README.md` | What it is (5 lines), Studio quick start, CLI quick start (the Bridge walkthrough in 5 commands), map of the docs, project layout, licence. Keep it under 150 lines. |
| `docs/studio.md` | Studio use, training queue, crash recovery and `training-active.json`, replay limits, `--replay-node`, `--run`, comparison view, recordings |
| `docs/experiments.md` | Rules for experiments; manifests; first run; declaring comparisons; resume, rerun, parallel trials and shards; tune and confirm; transfer and checkpoint selection; notes and tags; archives and compatibility (including keyed tables against list-backed archives); manifest reference table |

| `docs/agents.md` | The agent interface; episode completion (`finish`) and `learn_context`; an index of the learners linking to `agents/<name>/README.md` |
| `docs/analysis.md` | `analyze.py`; fixed-suite statistics; multiple arms against one reference; sequential tests; learning curves; oracles (full-state, reactive, history, clock, discounted); HTML reports; arena tournaments |

Move text verbatim first, in one PR, then edit for flow in a second PR, so reviewers can check that nothing was lost. Check that every paragraph of the old file appears in exactly one new place.

### D5. Map each experiment rule to what enforces it (M)

For each of the nine "Rules for experiments", list the laws (by file and name) and the host-side tests that enforce it, and say plainly which parts are only tested, not proven. Example: the seed-block disjointness in rule 5 is enforced by `checkSeedBlocks` and its tests, not by a law. This becomes the main entry point to the proofs.

### D6. Command reference (S)

Generate `docs/commands.md` from the usage strings in `experiment.mjs`, `batch.mjs` and the other CLIs, or write it by hand and let D1 rule 5 keep it in sync. Each command gets one line of purpose and one example.

### D7. Learner READMEs (S)

Each `agents/<name>/README.md` uses the same headings: what it learns, its parameters, how it handles episode ends, its laws, its checks, and an example plan.

## Verification gates

Every PR in phases 2 and 3 must pass these.

| Gate | Check |
| --- | --- |
| **G1. Tests** | `npm test`; `cd mcp && npm test`; the Python suites; full CI including Bend checks, all `--verdict` proofs and Windows |
| **G2. Archived source set unchanged** | Write a script that computes, for every training manifest in `experiments/`, the map of archived file names to SHA-256 digests that `sourceFiles()` would produce. Run it before and after each move, without Bend. The maps must be identical except for runner files deliberately changed in M0, listed in the PR. For one small plan per world type, CI also compiles and compares `toolchain.backend`. |
