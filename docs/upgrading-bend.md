# Upgrading Bend

The [Bend upgrade watch](../.github/workflows/bend-upgrade-watch.yml) runs every Monday at 08:27 UTC and can be dispatched manually from the default branch. It is advisory: it never runs on pull requests, never changes pins or baselines, and is not a required merge check. The Linux probe selects the highest stable official 2.x release, verifies the GitHub-published SHA-256 for its Linux x64 asset, and runs the Node suite, Bend checks, BendTT verdicts and representative backend gate. Node and Lean stay pinned. The backend gate compares the compiler version as well as hashes, so a new version can trigger a warning even when emitted bytes match.

On failure a separate job opens or updates the single watch issue with the fixed test-stage names, their GitHub-reported results, and a link to the job logs. It does not fetch or repost raw logs. The test job has read-only repository access and does not receive the issue-writing token; the issue job never checks out the repository or runs the candidate compiler. A successful probe leaves issue disposition to a maintainer.

## Upgrade checklist

1. **Review the compiler release.** Verify the official asset URLs and SHA-256 digests for each target. Use a clean branch and a separate candidate compiler path. Confirm the version, supported platforms and any base-library or code generator changes; keep the pinned compiler available for the control run.
2. **Compare archive identities.** Run the source/bundle gate unchanged. Compare a candidate `capture-backends` report saved outside the checkout against the [baseline and reviewed transitions](../tools/archive-gates/README.md), including compiler version and each before/after SHA-256. If the candidate changes a backend or any `core/` bytes, require an explicit reviewed transition with scope, exact hashes and rationale. Do not regenerate the checked-in baselines or make a failing gate accept arbitrary drift.
3. **Verify behavior and proofs.** Run root and MCP tests, all Bend checks and every `--verdict` using the pinned Lean independently. Confirm the tested learners and worlds reproduce their expected fixtures; a backend diff is not by itself a behavior change or evidence that a proof holds.
4. **Replay historical archives.** Run the G4 historical harness with the checked-in archive fixtures. Verify Replay and Studio/MCP attachment and resume without modifying any sealed archive or substituting the candidate backend for saved bytes. Run both Linux and Windows CI and the fresh devcontainer job on the final upgrade.
5. **Update setup and documentation together.** Change the reviewed Bend version, archive URLs and hashes in setup and required CI. Keep Node and Lean pins unless an independent review justifies changing them. For any Node change follow the [Studio SQLite startup and warning check](studio.md#if-studio-stops-during-training); SQLite is built into Node and does not need a separate dependency. Update the README, setup guide and test guide, then rerun the docs check.
